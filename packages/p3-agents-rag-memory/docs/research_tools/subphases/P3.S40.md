# P3.S40 Technical Specification

## Scope

P3.S40 is the integration and qualification plane for the research-tool extension. It owns runtime composition, evidence normalization, observability, qualification and supplemental downstream contracts. It does not own corpus, market, macro, company or quantitative algorithms.

## Public runtime contract

The gateway implements the pre-existing `ToolGatewayPort`:

```python
async def execute(request: ValidatedToolCallRequestRecord) -> ToolExecutionResponse
```

The dispatcher resolves an immutable `(tool_id, operation_id)` key, validates the request model, blocks network transports outside LIVE, applies a bounded timeout, validates the result model and maps it into the exact response type already consumed by S21.

## Evidence bridge

The existing S21 validator requires all non-synthetic evidence IDs to exist in `RetrievalEvidenceMap`. S40.M04 therefore executes between M03 and M04 of S21. It produces:

- `research_tool_result_envelope_panel`;
- `research_tool_evidence_map`;
- `extended_retrieval_evidence_map`;
- `research_tool_execution_trace_panel`.

Evidence is projected into the legacy `EvidenceRef` contract without losing the richer P1/P2 provenance maintained in the S40 envelope.

## Qualification grain

Qualification is never declared at family level only. The canonical grain is:

```text
tool_id × operation_id × mode_id
```

Possible states are `QUALIFIED_LOCAL`, `DEGRADED`, `BLOCKED_UPSTREAM` and `FAILED`.

## Downstream boundaries

P4 receives metrics and evidence references, not raw documents. P9 receives immutable learning evidence and associates it with matured outcomes later. Both producer contracts are ready, but the current consumers remain unwired. P5 is not a direct consumer.

## Failure behavior

Normal lack of upstream data is represented as `BLOCKED_UPSTREAM` or `DEGRADED`. Contract, schema, authorization, temporal, timeout and provider failures are mapped to existing S21 execution statuses. No empty payload is treated as silent success.
