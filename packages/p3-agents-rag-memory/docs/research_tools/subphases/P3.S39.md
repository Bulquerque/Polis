# P3.S39 — Quantitative Diagnostic Tool Suite

## Purpose

`P3.S39` provides small, deterministic, point-in-time-safe quantitative
calculations that an agent may use as evidence during cognition. It is not a
second feature engine, model layer, backtester or portfolio engine.

## Tool family

```text
quant.diagnostics.v1
```

Operations:

```text
return_statistics
realized_volatility
drawdown
correlation
entropy
event_window
scenario_shock
```

Modes:

```text
BASIC
ROBUST
STABILITY
```

A mode changes diagnostics and validation depth; it never authorizes searching
for the best result.

## Architecture

```text
P3.S33 PIT boundary
        ↓
quant handlers in P3.S39
        ↓
handler bundles and method manifests
        ↓
P3.S40 registry, ToolGatewayPort and evidence projection
        ↓
existing P3.S21 cognition
```

The package exposes only ports and handlers. It has no network client and no
file-system discovery logic.

## M01 — returns, volatility and drawdown

### Return statistics

Conventions are explicit:

- simple or logarithmic returns;
- sample standard deviation with `ddof=1`;
- requested annualization factor;
- requested quantiles;
- robust mode adds trimmed mean and median absolute deviation.

Frequency is never inferred silently.

### Volatility

Supported estimators:

- close-to-close annualized sample volatility;
- Parkinson high-low estimator;
- Garman-Klass OHLC estimator.

Range estimators require complete valid OHLC data. The implementation compares
estimators and reports missing prerequisites; it never selects the estimator
that produces a preferred answer.

`STABILITY` may add a seeded moving-block bootstrap interval. The seed, sample
count and block length are part of the request and therefore part of replay.

### Drawdown

The wealth index starts at an explicit positive value. Outputs include maximum
and current drawdown, peak, trough, recovery and the complete drawdown path.
No observation after `decision_time` enters the path.

## M02 — dependence and entropy

### Correlation

- Pearson and Spearman;
- inner alignment on `observation_time`;
- no forward fill;
- no automatic lag search;
- constant series and insufficient samples return a degraded outcome rather
  than a silent non-finite value;
- stability mode supports paired moving-block resampling.

### Entropy

Shannon entropy uses a versioned discretization policy:

- equal width;
- equal frequency;
- fixed edges.

Permutation entropy uses ordinal patterns with embedding dimension and delay
fixed by the request. Ties are resolved deterministically by original position
and the tie-window count is reported.

The implementation never chooses bins or embedding dimensions because they
maximize a result.

## M03 — event windows and scenarios

### Event window

- the event itself must be visible at `decision_time`;
- the full pre/post window must be observable;
- the anchor is the first observation on or after the event timestamp;
- optional benchmark adjustment requires aligned timestamps;
- placebo offsets are explicit inputs;
- outputs are descriptive and do not assert causality.

### Scenario shock

The operation evaluates explicit linear and quadratic exposures:

```text
scenario_value = baseline
               + Σ beta_i × shock_i
               + Σ gamma_ij × shock_i × shock_j
```

It does not estimate probabilities, optimize shocks or produce a recommendation.
Sensitivity multipliers are explicit and deterministic.

## M04 — qualification

M04 combines the three handler bundles, rejects duplicate operation IDs and
produces a qualification record for every `operation × mode` combination.
Qualification requires contract, property and leakage evidence. Promotion
authority remains with P0.

## Failure policy

Normal data limitations use explicit outcomes and reason codes. Contract,
handler or temporal invariant violations fail closed. Non-finite numerical
outputs are rejected by the result model.

Qualification hardening is fail-closed: unproven PIT statuses are rejected,
observations after the decision/as-of time are excluded, and evidence keeps
`source_artifact_id` when the canonical P2 record does not expose a shorter
artifact alias. Event time normalization is limited to the versioned
`observed_at`/`reference_date` daily adapter. M04 does not qualify empty,
status-only or hash/lineage-incomplete test reports.

## Runtime dependencies

Required runtime dependencies added by this patch: **none**.

The implementation uses the Python standard library plus the Pydantic contract
layer already required by the P3 package. NumPy, SciPy, pandas and `arch` were
reviewed as reference implementations but are not runtime dependencies.
