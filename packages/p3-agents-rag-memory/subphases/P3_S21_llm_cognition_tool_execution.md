# P3.S21 — LLM Cognition & Tool Execution

## 1. Missão

Executar cognição em duas etapas com structured output, tool requests governados, execução por adapters, validação point-in-time e continuação materialmente consciente dos caminhos `NO_TOOL`, rejeição, falha e sucesso.

## 2. Escopo

A subfase produz leituras, propostas de crença, intents e resultados de ferramentas validados. Ela não finaliza evidence binding, commitments, estado persistente, relações, memória ou features econômicas.

## 3. Dependências

- Upstream: `P3.S2.M02`, `P3.S15.M02`, `P3.S16.M01`, `P3.S16.M02`, `P3.S20.M05`, `P3.S20.M07`.
- Downstream: `P3.S22.M01`, `P3.S22.M02`, `P3.S24.M01`, `P3.S24.M03`, `P3.S26.M02`, `P3.S27.M02`.
- Runtime ports: `LLMPort`, `ToolGatewayPort`, `ClockPort`, `PromptCatalogPort`.

## 4. Módulos

1. `P3.S21.M01` — initial cognition planning without tool execution.
2. `P3.S21.M02` — deterministic request authorization.
3. `P3.S21.M03` — bounded, audited adapter execution.
4. `P3.S21.M04` — schema, provenance, linkage, and PIT validation.
5. `P3.S21.M05` — continuation after every possible tool-path state.
6. `P3.S21.M06` — discriminated typed belief parsing.

Detailed implementation: `docs/05_IMPLEMENTATION/P3_S21/MODULE_BY_MODULE.md` after overlay installation.

## 5. Ordem de execução

```text
M01 → M02 → M03 → M04 → M05 → M06
```

`M03` receives only accepted requests. Empty panels are valid and preserve the canonical no-tool path.

## 8. Limites de autoridade

- No trade decisions, targets, rankings, portfolio weights, or future-return fields.
- No direct vendor SDK use inside domain/runtime code.
- No direct mutation of entitlement, person state, belief state, relationships, or memory.
- No silent repair of invalid upstream artifacts or provider failures.

## 9. Invariantes e configuração

All models are strict, immutable, `extra=forbid`, timezone-aware, lineage-carrying, and versioned. Prompts are file-backed and hash-bound. Tool budget is the minimum of person entitlement, cognition default in gateway policy, and gateway hard limit.

## 10. Falhas

Failures are typed and fail closed. Provider failures remain material; future or schema-invalid tool results cannot become valid cognition evidence. A single structured-output repair is permitted; forbidden fields fail immediately without repair.

## 11. Observabilidade

Every provider request/result and tool execution records run/cycle/transaction/person IDs, prompt/model versions, request/response hashes, status, latency, retries, cost, and redacted credential-handle use. Secrets and raw authorization data are forbidden.

## 12. Testes

Canonical plan specification: `tests/specifications/subphases/P3_S21_TEST_SPEC.yaml`.

Functional tests added by this overlay cover all six wrappers, full tool and no-tool paths, retry, provider failure, temporal leakage, schema failures, structured-output repair, provider/proposition compatibility, generated schemas, HTTP mock transport, and replay.

## 13. Definition of Done

- Six module paths implemented with original IDs and IO preserved.
- Fifteen output schemas generated from runtime models and validated under Draft 2020-12.
- All local and integrated P3 tests passing.
- Global provider/proposition authorities preserved.
- Module registry hashes regenerated by the integration master.
- P0 qualification completed before any production claim.
